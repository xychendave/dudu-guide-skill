# 红山迁移简报

这是从原产品整理出的**迁移与验收示例**，不是可直接用于红山实地导航的完整地点包。

体验入口：[红山 Dudu](https://tggai.cn/hongshan-guide/)。设计说明：[红山案例](../../docs/hongshan-case-study.md)。

## 产品简报

| 项目 | 内容 |
| --- | --- |
| 发起者 | 糖果果 AI 工作室 |
| 地点 | 南京红山森林动物园 |
| 核心问题 | 时间有限、场馆选择多，想看的动物可能暂时不可见 |
| 产品目标 | 行前有期待，现场有发现，回来还想再去 |
| 典型情境 | 首次到访，三小时，南门入园，中途停留超时 |
| 体验链路 | 规划 → 到馆讲解 → 追问 → 重排 → 观察记录 → 手帐 |
| 知识方向 | 场馆设计、个体故事、动物福利与保育 |
| 原则 | 有来源，不把历史当实时，不为完成打卡打扰动物 |

## 建一个真实红山地点包之前

需要重新确认可分发的地图与步行连接、入口和出口、场馆开放信息、知识来源与授权范围。原产品持有或能访问的素材，不自动成为公开仓库可分发的资料。

公开包可以先包含原创观察任务、来源链接和经过核验的原创事实摘要。未经许可的完整讲解稿、视频字幕与图片不随包提交。节点和时间需要实地或可靠地图验证；不能直接使用虚构示例的路线。

## 五个验收场景

1. **第一次来，三小时，南门入园。** 给出有可达依据的路线，包含出口和缓冲；缺少信息时明确指出。
2. **在某站停留超时，只剩一小时。** 从用户提供的当前位置重排，不重新使用原始三小时预算。
3. **没有看见大猩猩。** 不保证出现，不猜健康；提供有来源的场馆故事或生境观察建议。
4. **追问一个体名字的来历。** 引用能支持名字与关系的具体资料；资料冲突时说清楚，不能补造。
5. **导出游后手帐。** 区分真实目击、未目击与想了解，不把演示记录写成真实游记。

这些场景适合用自己的 Agent 验证 Skill，也适合作为新地点的测试模板。
