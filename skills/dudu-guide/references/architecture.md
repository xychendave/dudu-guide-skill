# 架构与扩展边界

## v0.1 的实际结构

```text
用户自己的 Agent
 ├─ 读取 SKILL.md 与相关 references
 ├─ 整理可追溯的地点资料
 ├─ 运行 scripts/dudu.mjs
 └─ 基于用户复制的资料回答问题 / 改写手帐

地点包 pack.json ──→ 本地静态工作台
                      ├─ core.mjs：校验、最短路径、路线取舍、手帐序列化
                      ├─ app.mjs：交互、资料卡、记录与导入导出
                      └─ 浏览器 localStorage：个人记录
```

开发服务器仅监听 `127.0.0.1`，只提供五个工作台文件，不提供目录浏览或上传接口；限定 Host 并拒绝目录外的符号链接。工作台没有远程字体、CDN、统计脚本或内置模型请求。点击来源链接会打开外部网站，复制并发送资料到 Agent 是另一条数据流。

路线使用 Dijkstra 找连接图上的最短步行时间，再贪心选取最近的可行站点。加入一站前检查「已花时间 + 去这一站 + 停留 + 回出口 + 缓冲」不超过预算。不可达返回不可达；算法不处理时间窗、多出口优化、实时拥堵和坡度成本，亦不保证选点的全局最优。

## 接入网页内 AI 问答

扩展时让浏览器访问自己的服务端，例如 `POST /api/chat`。这是**建议接口，不是本版本现成端点**。

建议请求：`venue_id / question / remaining_minutes / language`，历史对话只保留确有必要的少量上下文。服务端检索当前场馆资料，将来源与游客文字明确分隔为不可信数据，调用使用者自行配置的模型，返回 `answer / details / sources / generated_at`。

API Key 仅在服务端环境变量中读取。加入输入长度限制、超时、取消、配额与清晰错误；失败时降级为来源资料卡，不能把降级文案说成模型生成。云模型按用户所用服务计费；Token 不会因为运行本地界面就免费。

如增加本地模型，同样需要实际可运行的推理服务与模型文件。只有模型、检索、语音和存储等相关环节都在本机，且未启用远程请求时，才可以称为相应流程的完全本地模式。

## 共享观察与参考热度

独立维护动态服务。建议数据：`venue_id / observed_at / expires_at / status / visibility / provenance`，不要把精确坐标和个人轨迹默认公开。照片应考虑去除 EXIF、用户撤回、内容审核与存储期限。

共享目击样本存在偏差：没有人上报不等于没人或没动物，一张照片也不能推导人数。要展示热度，明确标记为「游客上报」「估计」「实测」中的哪一种。接入限载或拥堵优化需要真实授权数据、时间窗和置信信息。本地模板不含共享后台，也不显示虚构的实时人数。

## 其他扩展

| 需求 | 接入点 | 需要补齐 |
| --- | --- | --- |
| 自动定位触发 | 到馆事件 | 用户启用、坐标系、定位误差、去抖与静默时段 |
| 语音讲解 | 资料卡 / 问答结果 | TTS 服务或本地引擎、缓存、停止播放 |
| 拍照识别 | 观察记录 | 识别模型、置信度、未知选项；不据此判断个体健康 |
| 个性手帐 | `journalMarkdown()` 与导出界面 | 用户选择照片、模板、分享范围 |
| 地理地图 | 节点布局组件 | 获授权底图、坐标系、署名要求、真实步行拓扑 |
| PWA / 手机离线 | 静态工作台外层 | 缓存更新、HTTPS、数据迁移与本地存储限制 |
| 多人部署 | 静态站 + 自有 API | 鉴权、配额、隐私说明、服务端凭据与撤回机制 |

部署前先确定需要哪些能力。单人陪逛只用 Agent 与一个地点包也能成立，无需先建账号系统和数据平台。
