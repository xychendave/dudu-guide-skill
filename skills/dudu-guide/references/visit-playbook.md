# 主动陪逛：少一点灌输，多一点发现

## 行前：让选择变简单

输入优先级：可用时间 → 当前/入园位置 → 出口 → 明确想看 → 行动条件。把场馆列表变成可执行的几站，并说明为何取舍。预算包含步行、停留、休息缓冲和出口距离。

例如：

> 我第一次来，有三小时，从南门入园，想看灵长类。

输出一条有时间估计的路线、可选替换点和信息不确定的地方。没有当天开放数据时，写「开放状态待现场核实」，不要编写今日演出、喂食时间或排队人数。

## 到馆：先给一个观察入口

触发可以是用户说「我到熊猫馆了」、点击到馆、扫描用户设置的二维码，或者已明确开启的定位事件。每种触发都要真实实现，不能把手动按钮描述成自动 GPS 讲解。

建议讲解顺序：

1. 一两句有来源的场馆特色或故事。
2. 一个具体可见的观察对象：空间、动作、材质、植被、展板。
3. 两三个可选追问，允许游客就此停下。

长短由现场节奏决定。快速追问先给 20 秒左右的短回答，细节在用户继续问时展开。来源可放在界面的来源区或回答末尾，不把长 URL 读出来。

## 超时：从「现在」重新出发

保留已完成记录，重新确认当前点与**从现在开始**的剩余时间。不要把原始总时长再次当作剩余预算。优先保留明确的重点、实际通行路径和出口缓冲；预算不够就减少站点，解释舍弃了什么。

模板使用最近可行点的贪心排序，不保证全局最优，也不处理营业时间窗口。真实地点若涉及预约时段、陡坡、台阶或闭馆，以经过核实的条件约束路线；不能满足时明确报告。

## 没看见：保留真实，扩展观察

不要说「再等五分钟一定出来」。可以尝试：

- 看生境：遮蔽、可选择的高度、阳光、阴影、水体与活动空间。
- 看故事：根据来源介绍场馆设计或保育经历。
- 做观察：记录一个声音、一种空间选择，或一个没有答案的问题。
- 换节奏：看附近已确认可达的地点，或者把这次期待留到下次。

不能凭没看到就判断动物生病、饲养不当或已经转移。鼓励安静观察，不用投喂、呼喊或拍打来完成图鉴。

## 游后：把记录变成自己的故事

依据用户真正记录的内容生成「今天遇见」「新的发现」「还没解开的疑问」「下次想再来」。`seen: false` 不能写成目击；演示数据不能写成真实经历。可重新组织表达，但不编造同行者、照片、对话和时间线。

分享版只纳入用户选择的内容。精确时间、位置和人物信息是否公开由用户决定；不默认把整份个人备份上传社区。
