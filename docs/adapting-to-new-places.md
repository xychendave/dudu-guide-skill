# 把 Dudu 带到不同地方

## 迁移的不是地名，而是发现方式

替换一个地点时，至少要重新核实入口与出口、真实步行连接、可用时间、故事来源、现场活动边界。地图与讲解不是简单的字符串替换。

| 地点类型 | 值得组织的知识 | 现场观察切口 | 需要避免 |
| --- | --- | --- | --- |
| 动物园 | 个体故事、生境设计、保育工作 | 空间选择、行为、遮蔽与环境 | 保证目击，鼓励投喂或引诱 |
| 植物园 | 物种、季相、生境、栽培历史 | 叶形、气味、光照、植物群落 | 未经核实承诺花期；触碰或采摘受保护植物 |
| 博物馆 | 藏品来源、材料、工艺、历史语境 | 一个细节、一组对比、一条展陈线索 | 编造藏品故事或忽略拍摄规定 |
| 自然公园 | 生态、生境、地貌、步道 | 声音、环境变化、远距离观察 | 引导离开开放步道或靠近野生动物 |
| 展览 | 策展主题、作品、作者、展签 | 形式、材料、作品之间的关系 | 冒充作者意图或把评论说成事实 |

## 三种可直接交给 Agent 的请求

### 为植物园做两小时版本

```text
使用 dudu-guide，为我提供资料的这座植物园做游园搭子。
两小时，入口和出口相同，以植物与环境的关系为主题。
先核实开放区域和可达连接，每站提供一个观察任务。
没有实时花期资料时，不要承诺能看到某种花开放。
生成本地工作台，列出仍需我核实的资料。
```

### 为博物馆做「只看六件」版本

```text
阅读 dudu-guide Skill，根据我给的官方展览介绍和楼层图，
为 90 分钟参观挑选最多六个重点。
考虑楼层移动与出口时间，别把平面直线当可走路线。
每件先讲一个有来源的细节，再给一个可以自己观察的问题。
文字保持自然，不假定我是儿童。
```

### 用已有游园记录制作手帐

```text
使用 dudu-guide，把我提供的 JSON 记录整理成一页游园手帐。
保留「看见了」和「暂时没看见」的区别，不编造照片与经历。
分成今天的相遇、新发现、未解的问题和下次期待。
先在本地生成 Markdown，我会自己选择是否公开分享。
```

## 贡献一个地点包的最小做法

在自己的分支中建立 `examples/<place-id>/`，放入 `pack.json`、简短 README 和来源/素材说明。先跑结构校验，再运行工作台测试。真实包不得混入虚构资料；来源缺失、授权不清楚的内容只提交问题描述或引用链接。

README 说明适用范围、核验日期、路线时间依据、已知限制、哪些素材由你原创、哪些仅可引用。个人使用可以有私有扩展，提交公开 PR 前只保留可公开的数据。

## 个性化的好起点

想让搭子更像自己的作品，可以先改观察任务、短讲解的语气、手帐内容组织与视觉主题。增加功能前，先试一次「少一个小时」「一个重点关闭」「什么都没看见」：如果这些情况下它仍能清楚、有分寸地陪逛，产品基础就更扎实。

涉及实时位置、共享照片、多人服务和模型请求的改造，按 [架构](../skills/dudu-guide/references/architecture.md) 补齐实际能力和数据流，不只改界面文案。
