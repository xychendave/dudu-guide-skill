# 红山 Dudu：让游园的收获不止于「看到了」

参考产品：[红山 Dudu 游园](https://tggai.cn/hongshan-guide/)。本案例基于创作者提供的产品介绍，以及 2026-09-05 对相关线上页面与部署代码的只读检查。实现核对不等于每个线上服务都经过端到端或高负载验证。

## 出发点：一份真实的期待与落差

糖果果和陈同学是 B 站科技生活区创作者。四年前的一次家庭动物园出游，让他们对游园形成了初步印象；后来带着自己做的 Dudu 去红山实测，又获得了不同的发现。

行前调研和现场体验中，一个问题很突出：游客期待见到某只动物，但动物可能休息或暂时不在视野里。这时，工具能否帮助游客继续获得有价值的体验？

Dudu 的回答是把观察从动物出现的瞬间扩展到整个场馆：空间为什么这样设计，保育员关心什么，个体有哪些有出处的故事，这里鼓励游客如何认识自然。目标不是诱导动物配合打卡，而是丰富游客的注意力与理解。

产品介绍中「丰容」被借作对游园体验的愿景。本文记录这个设计灵感，不把它当作经过研究验证的产品效果。

## 一次典型使用

```mermaid
flowchart LR
    A[首次到访 / 时间有限 / 入口明确] --> B[选场馆与规划路线]
    B --> C[手动到馆 / 生成讲解]
    C --> D[基于资料的追问]
    D --> E{现场情况变化}
    E -->|时间变少| F[从当前位置重排]
    E -->|没有看见动物| G[观察生境与故事]
    F --> H[记录一次发现]
    G --> H
    H --> I[图鉴 / 手帐 / 下次期待]
```

比如一位第一次来的游客，只有三小时，从南门入园。产品先把入口、时间和兴趣转换成路线，减少面对大量信息时的选择负担。到馆后，讲解结合该站在整段行程中的位置与用户可用时间，讲一点当前值得关注的内容；游客可以继续问设计意图、保育故事或观察方法。

中途停留超时，就根据现在的进度调整。没看到动物，也能观察空间或阅读有来源的故事。游后用自己的记录留下图鉴与手帐，形成下一次游园的期待。

以上为产品情境描述，不是公开用户行为日志。

## 从实现中提炼出的可复用部分

| 原产品组件 | 检查到的机制 | 开源抽象 |
| --- | --- | --- |
| `plan.html` | 时间/入口/场馆选择，路线图与中途调整 | 地点节点、步行边、预算和进度 |
| `route-app.js` 与路线数据 | 场馆与地图点位关系 | 地点包中的空间层 |
| 问答与讲解服务 | 按场馆检索；区分全园 Dudu 与场馆角色；生成讲解/追问回答 | 一个协调角色 + 当前场馆的资料上下文 |
| 资料与精选事实 | 场馆内容、园方文章、精选事实来源 | 来源索引、事实卡与时间说明 |
| `field/app.js` | 图鉴、观察与打卡流程；存在识别和共享服务请求 | 个人发现记录 + 可选服务接口 |
| 参考热度图 | 时段、热门场馆与共享动态参与估算 | 明确标注来源和不确定性的动态层 |

「场馆子 Agent」在产品表达上很好理解，但就检查到的问答代码而言，全园与场馆角色由上下文、检索范围和提示词区分。这不等于每个场馆都有一个独立常驻进程。对开源迁移而言，先做好场馆知识范围，比机械增加 Agent 数量更重要。

## 知识是怎么组织的

检查到的服务按场馆读取资料，并检索园方内容和精选事实来补充回答；提示词要求不编造事实、不把旧报道当实时状态，并用短回答与展开细节来适应现场节奏。

创作者介绍中的视频流程是：找到官方精品内容，取得可处理的字幕或音频，转写并核验，整理到场馆知识中。以大猩猩个体故事为例，名字、来历、日期与迁移背景都应能追溯到具体材料，而不能只靠模型知道一种动物的一般知识。

本次检查的公开发布入口与相关代码中没有确认一套完整可移植的视频采集/转写流水线，因此开源版本把它写成方法和扩展接口，不声称已附带可直接执行的一键管线。也未将原始场馆稿或完整转写公开。

## 哪些地方必须准确表述

**参考热度不等于实测人数。** 检查到的热度图结合时段规律、热门场馆与共享动态估算，页面也有估计说明。它可以启发路线产品设计，但不能据此声称已接入真实限载、闸机客流或拥堵预测系统。按实时人数优化路线仍需要真实数据和验证。

**到馆触发不等于持续自动定位。** 原产品有手动到馆、场馆切换及部分位置使用。任何「走到哪里自动讲到哪里」都应对应实际启用的定位和触发机制；本开源模板明确采用手动到馆。

**本地界面不等于完全本地 AI。** 线上服务使用模型接口，本地模板则由用户的 Agent 完成对话。若用户的 Agent 使用云模型，请求会离开本机。

**可观察到功能不等于已证明效果。** 本项目没有发布游客满意度、看到动物的概率、耗时改善等量化评估。演讲中的体验描述应保持为创作者体验，不转换成统计结论。

## 从红山走向别的地方

我们保留的是「选择—观察—追问—调整—记录」的关系。把红山的地点资料换成植物园的植物与生境，或博物馆的藏品与历史，方法仍能成立。

公开仓库里的默认示例是一座虚构自然园，帮助贡献者先验证这条链路。红山的地图、影像、官方讲解稿、运营数据与模型凭据没有随同进入公开包。这样社区可以从清楚的起点创建自己的内容，并独立选择模型、存储、服务和分享范围。

未来最值得共建的不只是更多按钮，也包括更准确的地方知识、更可靠的步行图、更有分寸的观察建议，以及能让游客愿意再次出发的记录方式。
